# Dow Theory Daytrade Strategy（検証用）

`Dow Theory Daytrade Entry.pine` のシグナルロジックを一切変えずに `strategy()` 化し、
**コスト差引後の期待値・ドローダウン・レジーム別成績を実数で出す**ための版。

インジケーター版は「シグナルが見える」ところまでで、勝率・平均RR・最大DD・
期待値がどこにも数値で出ていなかった。エッジの有無が未検証の状態だったので、
そこを測るための道具。

---

## 1. なぜ別ファイルにしたか

インジケーター版はチャート上での判断に使う道具、こちらは検証専用。
役割が違うので混ぜない。**インジケーター版のロジックは1行も変更していない。**

シグナル部分は機械的に移植し、移植後に差分を突き合わせて検証済み。
差異は「描画コードの削除」と「未使用の idx 変数の削除」だけで、
比較演算子・状態遷移・条件式は完全に一致している。

唯一の意図的な置き換えは、エントリー成立行の

```
showDayEntry and dayBarOK and ...   →   barstate.isconfirmed and ...
```

`showDayEntry` は表示トグル、`dayBarOK` は既定 `dayConfirmedOnly=true` のとき
`barstate.isconfirmed` と等価。つまり既定設定での挙動は同じ。

**結論：本 strategy のエントリーはインジケーター版の DAY-L / DAY-S と1本単位で一致する。**
「見ていたものと違うものを検証してしまう」事故を避けるのが最優先。

---

## 2. 移植上の注意（既知の癖を温存している）

インジケーター版には次の挙動がある。**直さずそのまま移植した。**

`oshiBreakSignal1` / `modoriBreakSignal1` は2箇所で `true` になる。

1. スイング確定時のノイズフィルタ経路（`ssb_maxPrice1 > prevPeak1 + noiseThreshold` の中）
2. 終値ベースのブレイク判定（`close > modoriTakane1` の中）

ところがソース上の順序は **1 → リセット(`:= false`) → 2** なので、
1で立てたフラグはリセットで消え、トリガーには使われない。
つまり実際にエントリートリガーになるのは **終値ベースのブレイクだけ**。

これはインジケーター版で実際に出ていた DAY-L/DAY-S の挙動そのものなので、
検証対象としては温存が正しい。ここを「直す」と、
今まで見てきたシグナルとは別物を測ることになる。

直すかどうかは、まず現状の期待値を測ってから決めるべき判断。
直した版を試すなら、この strategy をコピーして
`oshiBreakSignal1 := false` のリセット行をノイズフィルタ経路より前に移し、
両方の数字を比べる。

## 3. 追加した検証装置

### ⑦ 検証期間 / IS・OOS 分割

カーブフィット検出用。SW1=7 / SW2=28 / SW3=112 は概ね4倍間隔で恣意性は低いが、
「たまたま良かった値」でないことは期間を分けないと言えない。

| 設定 | 使い方 |
|---|---|
| `検証ウィンドウ` = IS(分割前) | パラメータ調整はここだけで行う |
| `検証ウィンドウ` = OOS(分割後) | **最後に一度だけ**見る |

OOS を見ながら調整すると OOS は IS になる。ここが崩れると検証全体が無意味になる。
IS と OOS で期待値Rが大きく落ちるなら、それは相場ではなくパラメータを見ていた証拠。

### ⑦-2 取引時間帯

- `エントリー許可時間帯`（既定 0900-1430）… 引け直前の新規を除外
- `建玉保有許可時間帯`（既定 0845-1510）… 外れたら成行で強制決済

デイトレなので持ち越しは禁止。オーバーナイトのギャップリスクが混入すると、
測っているものがデイトレのエッジではなくなる。

### ⑧ リスク管理

- `1トレードリスク (%資産)` 既定 0.5% … %リスクベースのサイジング
- `最小発注数量に届かない場合は見送り` 既定 ON

  **OFF にしてはいけない。** OFF は「規定リスクを超える建玉を許す」意味になり、
  バックテストが現実より良く出る。
- `最大建玉数量` … 証拠金制約はモデル化していないので、口座の実力でここを止める
- `1日あたり最大トレード数` 既定 3 … 過剰取引の抑制
- `日次損失上限` 既定 2% … 到達したらその日は打ち止め

期待値がプラスでも、1回のロットが大きければ連敗の谷で資金が尽きて
「収束する前に退場」する。プラス期待値を持ちながら消えるのはここ。

### ⑨ 決済ルール

| ストップ基準 | 内容 |
|---|---|
| 構造（既定） | SW1 の押し安値/戻り高値。無ければ直近 B1/P1 |
| ATR | 現値 ± ATR × 倍率 |
| 遠い方 / 近い方 | 上記2つの比較 |

構造ストップが既定なのは、押し安値・戻り高値が
「多数の参加者が同じ場所を意識するので損切り注文が物理的に集積する」位置だから。
そこを基準に置くのは根拠のあるストップで、単なるパターン当てとは質が違う。

- `許容ストップ幅上限` 既定 ATR×4.0 … これより広くなるセットアップは見送る
  （リスクが読めない場面を統計から除外する）
- `建値移動` 既定 +1.0R で建値へ
- `ATRトレール` 既定 OFF
- `最大保有本数` 0=無制限。デイトレのエッジは短時間で出るはずなので、
  ここを絞って期待値が落ちないなら「持ちすぎ」が損失源だと分かる

分割決済は**意図的に入れていない**。数量分割は実装バグを生みやすく、
先に確かめたいのは「素の期待値がプラスかどうか」なので。

### ⑩ 集計

**サマリーテーブル**

| 項目 | 読み方 |
|---|---|
| 期待値 (R/回) | **最重要。** これがプラスでなければ他の数字に意味はない |
| 勝率 | 単体では何も意味しない。ペイオフレシオと対で見る |
| 平均利益/損失 (R) | |
| ペイオフレシオ | 勝率40%でもこれが2.0超なら期待値はプラス |
| プロフィットファクタ | |
| 最大DD | 通貨 / % 両方 |
| リカバリーファクタ | 純益 ÷ 最大DD |
| 最大連敗 | **サイジングの妥当性はここで決まる。** 最大連敗 × リスク% が耐えられるか |
| 支払コスト合計 | 実際に支払った手数料の実額 |
| 平均MFE / MAE (R) | 含み益/含み損の平均最大値。利確・損切り位置の妥当性 |
| 髭のみSL到達 | 後述 |
| 髭のみTP到達 | 後述 |

**髭のみSL/TP到達** — README の「髭到達と終値成立を分けて記述する」を集計に持ち込んだもの。

TradingView は逆指値・指値を**髭で約定**させる。つまりバックテスト結果は
「髭で刈られた損失」を全部カウントし、「髭で届いた利確」を全部成功にしている。

- `髭のみSL到達` = 初期ストップに髭では触ったが、終値では戻していた回数
- `髭のみTP到達` = 初期利確に髭では届いたが、終値では届いていなかった回数

**この比率が高いほど、バックテスト結果は「髭が都合よく動いてくれる前提」に依存している。**
20%を超えると警告色になる。ここが厚いなら、実運用の成績はバックテストより悪くなる。
指標を曖昧にしたままだとバックテストが自分に嘘をつくので、明示的に測る。

**レジーム別テーブル**

区分ごとに 回数 / 勝率 / 期待値R / PF を出す。

| 区分 | 意図 |
|---|---|
| 全体 | |
| LONG / SHORT | 方向の偏り |
| SW3 上昇 / レンジ / 下降 | **レジーム依存の検出** |
| 時間帯 A / B / C | 前場・後場・ナイト |

日経先物はトレンド期とレンジ期で押し安値ブレイクの信頼性が全く違う。
SW3 をフィルタに使っているのは良い設計だが、レジーム別に分けないと
**「平均すると勝てるが、レンジ期には確実に負ける」**状態が見えない。

サンプル30件未満の区分は `*` 付きの灰色で表示される。**灰色の数字は読まない。**
薄いサンプルの期待値は運とほぼ区別できない。

## 4. 使い方

1. TradingView で日経225先物（ミニ）のチャートを開く。想定は 15m。
2. `Dow Theory Daytrade Strategy.pine` をピンエディタに貼って「チャートに追加」。
3. **「プロパティ」タブでコストを実際の環境に合わせる。**
   スクリプト宣言の既定値は 手数料 50円/枚・スリッページ 1ティック。
   Pine の仕様上、宣言部の値は入力欄から変更できないのでここで設定する。
   支払った実額はサマリーの `支払コスト合計` に出る。
4. 設定の「⑧ リスク管理」で `1ポイント価値` を確認（日経225ミニは **100**、0のままなら自動取得）。
5. まず `検証ウィンドウ = IS(分割前)` で期待値Rを見る。
6. 最後に一度だけ `OOS(分割後)` に切り替える。

### 数字の読む順番

1. **トレード数** — 100未満なら判断材料にならない（警告色が出る）
2. **期待値 (R/回)** — プラスか。マイナスなら以降は見る必要がない
3. **髭のみSL/TP到達** — 厚いならその期待値は実運用で再現しない
4. **レジーム別の期待値R** — どこか1区分だけで稼いでいないか
5. **IS と OOS の落差** — 大きいならパラメータを見ていただけ
6. **最大連敗 × リスク%** — その谷を実際に座っていられるか

順番が大事。1と2を飛ばして3以降を眺めても意味がない。

## 5. この検証で分からないこと

正直に書いておく。

- **証拠金・追証はモデル化していない**（`margin_long/short = 0`）。
  `最大建玉数量` で頭を止めているだけ。
- **スリッページは固定ティック**。実際は板が薄い時間帯や急変時に大きく広がる。
  ナイトセッションや指標発表時の成績は楽観側に出る。
- **約定拒否・回線断・発注ミスは含まれない。**
- **15m 足のバックテストは足内の値動き順序を知らない。**
  同じ足でSLとTPの両方に髭が届いた場合、TradingView の仮定が実際と違う可能性がある。
  `髭のみSL/TP到達` はその依存度を測るための指標。
- **エッジは劣化する。** 一度プラスが出たら終わりではなく、
  期間を進めながら同じ数字を取り直し続ける必要がある。
  持続的に勝つ能力は「エッジを持つこと」ではなく
  「劣化を検知して作り直し続けること」の方にある。

期待値がプラスで出たとしても、それは「この期間・この銘柄・この時間軸・
このコスト前提で、過去はプラスだった」という意味しかない。
それでも、測らずに続けるより測ってから決める方が圧倒的にましというだけの道具。
